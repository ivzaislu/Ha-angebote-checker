# Архив акций Marktguru и обучающие данные

Архив пополняется при поиске и изучении листовок. Он сохраняет собственные снимки ответов Marktguru в таблице `offer_archive`: название, описание, магазин, страну, индекс региона, цену, сроки, распознанную разновидность, фасовку и исходный JSON. Исчезновение акции из API не удаляет сохранённые данные.

Одинаковый снимок не дублируется. Изменение цены, сроков, описания или региона создаёт новый снимок. Это история уникальных состояний акции, а не журнал каждого повторного просмотра: возврат к полностью идентичному ранее сохранённому состоянию не создаёт новую запись. Старую историю, которой нет в собственном архиве или доступных листовках, система не восстанавливает.

Для постоянного хранения нужен `DATABASE_URL` с PostgreSQL. Встроенная PGLite без него работает в памяти и очищается при перезапуске. Миграция `0003_offer_archive.sql` применяется стандартным механизмом проекта; существующие таблицы не удаляются. Старые записи `observed_prices` остаются на месте, но не преобразуются в полные снимки: у них нет исходных ответов, региона и сроков.

## Сбор по Германии

Из каталога `webapp`, с `DATABASE_URL` в окружении:

```bash
npm run db:migrate
npm run archive:collect -- 10115 20095 50667 60311 80331
```

Индексы задаёт оператор (1–30 за запуск); список выше — пример, не гарантия покрытия страны. Каждый регион собирается отдельно, последовательно. В каждом регионе сборщик запрашивает первую страницу (40 результатов) для каждого поискового правила и доступные продуктовые листовки, до 80 ссылок на предложения на листовку. Текущие и более старые доступные листовки обрабатываются вместе. Ссылки на одну акцию внутри региона дедуплицируются. Ограничения и ошибки API могут уменьшить покрытие; при ошибке команда завершается с ошибкой, уже сохранённые снимки остаются, повторный запуск безопасен.

Команда предназначена для запуска оператором или внешним планировщиком на сервере. Расписание автоматически не устанавливается. Ключи и механизм получения ответов используются из существующей интеграции; доступность актуального API нужно проверить в среде развёртывания.

## Поиск без повторного сбора листовок

«Найти акции» сначала читает последний сохранённый снимок каждого предложения для выбранных страны и индекса. Учитываются товар, разновидность, выбранные магазины и сроки действия; истёкшие и будущие предложения исключаются. Если срока окончания нет, снимок используется не дольше 24 часов после сохранения. Более старый снимок не подменяет последнее состояние акции. При найденных совпадениях запрос к Marktguru не нужен; архив может содержать лишь часть доступных акций.

Если подходящих действующих записей нет, выполняется короткий поиск только указанного товара в Marktguru. Полный сбор листовок выполняется отдельно кнопкой «Обновить листовки» или операторской командой `archive:collect`. Открытие страницы, изменение индекса и обычный поиск полный сбор не запускают. Наличие результатов в архиве не означает, что все предложения магазина уже собраны: для получения новых используйте явное обновление.

## История цен

Кнопка «История цен» в карточке показывает сохранённые предложения с таким же нормализованным названием по выбранной стране, от минимальной цены до максимальной. API `archivedPriceHistory` поддерживает дополнительный фильтр по индексу. Диапазон и количество рассчитываются по всем записям, детали ограничены первыми 500; интерфейс сообщает об усечении.

Фасовки и разновидности могут отличаться даже при одинаковом названии. Для сравнения показываются количество и цена за кг/л, когда их можно однозначно извлечь. Неизвестная цена не считается нулём. Это цены наблюдавшихся акций, включая истёкшие, а не актуальная доступность товара. Региональные копии считаются отдельными наблюдениями; количество наблюдений не равно количеству независимых акций.

## Разновидности и подготовка мини-ИИ

Распознавание пока основано на правилах: лосось/копчёный лосось/сейлахс/ветчина, молоко/пахта/растительные напитки, явные признаки Bio, без лактозы, vegan, замороженное, ассортимент и процент жира с подписью Fett. Неопределённые семейства и разновидности остаются `null`; отсутствие признака не означает его противоположность. Вариант и фасовка сохраняются отдельно от названия.

```bash
npm run archive:export -- training-candidates.jsonl
```

Экспорт читает собственный архив Германии и создаёт новый JSONL-файл (существующий не перезаписывается). В нём: схема версии 1, текст, категория, вариант, поисковое намерение, положительная/отрицательная метка, происхождение и `split`. Повторяющиеся тексты для одного намерения дедуплицируются. Все нормализованные одинаковые названия попадают в один split: детерминированный хеш назначает примерно 10% групп в validation, остальные в train; это не гарантирует наличие обоих классов в маленьком наборе. Синонимы ещё могут пересекать split и требуют проверки.

Метки `rules-v1` получены существующими правилами, а не человеком. Каждая запись содержит `needsReview: true`; неопределённые и противоречивые решения исключаются. Выгрузка не меняет веса модели и не является независимым эталоном для оценки качества. Перед обучением нужны проверка меток, балансировка и отдельная ручная тестовая выборка. Цена не используется как целевая метка классификации.
