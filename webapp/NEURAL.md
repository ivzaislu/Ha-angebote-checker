# Нейросеть товаров v2

Это небольшой классификатор соответствия пары «запрос — предложение». Он не управляет сервером, не придумывает цены, не меняет сроки акций и не заменяет проверку страны/индекса. В v2 — 512 входных признаков, 24 скрытых нейрона с leaky ReLU, sigmoid на выходе и 12 337 обучаемых параметров. Признаки: слова и символьные тройки названия/категории, слова описания, запрос и взаимодействия «запрос × текст». Обучение и применение используют одну функцию подготовки признаков. Модель работает на CPU, без внешней LLM или GPU.

## Что уже обучено

`product-curriculum.json` задаёт 128 авторских товарных названий с явными допустимыми запросами; они разворачиваются в 2048 пар; это учебные фразы, а не выгрузка реальных предложений Marktguru. `product-benchmark.json` задаёт 32 других названия, разворачивающиеся в 512 контрольных пар. Предметные группы: молоко/пахта/овсяный напиток, свежие/маринованные огурцы, масло, разновидности лососевых товаров, кофе, яблоки/сок и туалетная бумага. Имеются явно неподходящие товары, например техника и посуда.

`product-seed.json` — обученный учебный кандидат и отчёт. Он **не активируется автоматически** и используется как исходная оценка при подготовке предложений для ручной проверки. В приложении работает только версия, явно записанная в активный указатель PostgreSQL. Если её нет, применяются правила. Результат на авторской контрольной выборке не является оценкой точности на реальных акциях пользователя. Вероятности сети не откалиброваны.

## Обучение из собственного архива

После установки нового образа сначала примените миграции. Из корня проекта на сервере:

```bash
docker compose run --rm --no-deps migrate
docker compose exec -T app node --experimental-strip-types scripts/product-model.ts train --activate-if-qualified
docker compose exec -T app node --experimental-strip-types scripts/product-model.ts status
```

Тренер читает до 10 000 последних снимков Германии, получает слабые метки существующими правилами, дедуплицирует региональные/ценовые повторы и добавляет авторский учебный набор. Слабые метки имеют меньший вес, чем авторские и проверенные человеком. Число прочитанных снимков и ограничение выводятся в отчёте. Цена не служит целевой меткой классификации.

Все одинаковые нормализованные названия попадают в одну группу. Примерно 20% групп остаются для validation; остальные — для обучения. Все названия авторского контрольного набора полностью исключаются из обоих подмножеств. Синонимы и разные написания одного товара пока могут образовывать разные группы; это ограничение оценки нужно учитывать.

Используется SGD с весами классов, детерминированным перемешиванием, уменьшением learning rate и ранней остановкой по validation loss. Контрольный набор не участвует в выборе эпохи. Оценка на нём выполняется после выбора весов. Максимум по умолчанию — 40 эпох, допустимо `--epochs 1..100`. Тесты подтверждают: изменение контрольных меток не меняет обученные веса.

Кандидат и отчёт сохраняются в `product_models`. Отчёт содержит fingerprint данных, источники меток, шаги/эпохи, confusion matrix, precision, recall, balanced accuracy, log loss, Brier score, покрытие решений с высокими/низкими оценками и результаты по запросам. `accuracy` учитывает все классы и может быть завышена из-за множества отрицательных пар, поэтому дополнительно проверяются другие показатели.

Автоматическое включение допускается только при достаточных train/validation/control данных, accuracy не ниже 0.90, balanced accuracy не ниже 0.85, precision принимаемых с оценкой >=0.9 примеров не ниже 0.95 и покрытии крайних оценок не ниже 0.15 на validation и control. На контрольном наборе также не допускается ухудшение относительно действующей модели (или правил для первого включения) по accuracy, ложным положительным и ошибкам крайних оценок. Проверки выполняются на ограниченных данных и не гарантируют качества вне них.

Включённая модель используется только для запросов с проверенными положительными примерами на validation и control, достаточным recall и без ложных положительных на control. Неподдерживаемые запросы, незнакомый словарь и промежуточные оценки возвращают управление правилам. Жёсткие запреты на подмену продуктов сохраняются.

Если `eligible=false`, кандидат сохраняется для разбора, а активная версия остаётся прежней. При запрошенном `--activate-if-qualified` команда вернёт код 2. **Не обходите проверку прямым изменением таблиц**. Добавьте проверенные примеры, разберите ошибки и обучите новую версию.

## Ручные исправления

Подготовить до 100 автоматически размеченных примеров, в первую очередь с оценками около 0.5. Уже проверенные примеры и строки с описанием длиннее 600 символов или категорией длиннее 180 пропускаются, чтобы выгрузку можно было импортировать без изменения исходного текста:

```bash
docker compose exec -T app node --experimental-strip-types scripts/product-model.ts review /tmp/review.jsonl
docker compose cp app:/tmp/review.jsonl ./review.jsonl
```

В редакторе проверьте соответствие `intent` и товара. Исправьте `positive` на `true` или `false`, затем **только для проверенных строк** установите `reviewed:true`. Название, описание и категорию сохраняйте без подмены. Например, структура одной строки:

```json
{"intent":"Milch","name":"Buttermilch","category":"Milch","description":"500 g","positive":false,"reviewed":true}
```

Непроверенные строки пропускаются. Конфликтующие одинаковые примеры одного уровня доверия исключаются; проверенный человеком пример имеет приоритет над автоматическим при совпадении входных полей. Исправления для названий контрольной выборки не используются для обучения — иначе оценка перестанет быть отложенной.

```bash
docker compose exec -T app node --experimental-strip-types scripts/product-model.ts train --reviewed - --activate-if-qualified < review.jsonl
```

Проверенные метки сохраняются в `product_review_labels` и автоматически используются при следующих обучениях (до 10 000 последних проверенных меток за запуск); файл не нужно импортировать каждый раз. Противоречивые одинаковые строки одного файла отклоняются. Новый явный импорт может исправить ранее сохранённую метку. Файл не должен превышать 10 МБ/10 000 проверенных строк. Тренировка без `--activate-if-qualified` только создаёт кандидата.

## Версии и откат

```bash
docker compose exec -T app node --experimental-strip-types scripts/product-model.ts status
docker compose exec -T app node --experimental-strip-types scripts/product-model.ts activate PRODUCT_MODEL_ID
docker compose exec -T app node --experimental-strip-types scripts/product-model.ts rollback PREVIOUSLY_ACTIVE_MODEL_ID
# Отключить сеть и вернуться к правилам, сохранив все версии:
docker compose exec -T app node --experimental-strip-types scripts/product-model.ts deactivate
```

`activate` повторно проверяет кандидата относительно текущей версии и контрольного набора. `rollback` разрешён только на ранее включённую совместимую версию. Указатель меняется атомарно с проверкой предыдущего ID; параллельный старый тренер не может затереть более новую активацию. Все переключения записываются в `product_model_events`. Приложение подхватывает новый ID при следующем поиске; перезапуск для переключения весов не нужен.

При первом внедрении v2 старые веса `offer_brain` остаются в базе для совместимости словаря. Новая сеть обучается отдельно и не изменяется обычными запросами. Сбор листовок может поддерживать старый словарь, но не заменяет активную v2-модель. Обучение и активация доступны только операторской CLI; публичный интерфейс показывает состояние, но не позволяет менять веса.

Проверка учебного обучения без базы: из `webapp` выполните `npm run brain:seed`. Она выведет отчёт, не изменяя файлы или рабочую модель. Переобучение учебного файла разработчиком — `node --experimental-strip-types scripts/train-product-model.ts --write-seed`.
